## Escopo, diferença e rollback

Antes de R0 havia afirmações históricas de M0–M10, evidências em branches e
scripts de teste, mas faltava uma leitura atual do checkout e um plano de
consolidação. R0 registra a topologia, as capacidades e os resultados locais,
sem mudar regras de domínio, API, contratos, schema, migrations ou dados de
negócio. Corrige a dependência de build da API e do worker em relação ao pacote
Prisma, após reproduzir uma corrida no build Docker. A correção altera somente
`apps/api/package.json`, `apps/worker/package.json` e `pnpm-lock.yaml`.

**Contratos e migração compatível:** não há novo endpoint, evento, payload,
OpenAPI, tabela ou migration. `pnpm api:generate` reproduziu o cliente sem diff.
O rollback da correção é reverter esse commit de metadados de workspace;
nenhuma restauração de banco ou objeto é necessária. Não reverter migrações ou
desfazer dados reais como parte do rollback de R0.

## Validação local de R0

Ambiente observado: Node.js 22.22.1, pnpm 11.25.0, Docker Compose v5.6.0;
PostgreSQL 17, MinIO, ClamAV, API e web locais apareciam ativos no
`docker compose ps`. Containers ativos foram iniciados antes deste commit;
construir imagens não os reiniciou nem prova deploy do código R0.

O primeiro `pnpm test:e2e` parou antes dos testes porque o sandbox impediu o
Next.js de escutar em `127.0.0.1:3320` (`EPERM`). Repetido com acesso local
autorizado, passou 40/40. Os testes regeneraram 12 PNGs históricos rastreados;
eles estavam limpos antes da execução, foram conferidos e restaurados após o
teste. Não há evidência visual nova incorporada ao commit.

O primeiro `docker compose build` falhou com erros TypeScript do cliente Prisma.
Uma repetição sem alteração passou, sinalizando condição de corrida. O grafo do
Turbo iniciava API/worker enquanto `database#build` ainda gerava o cliente. Após
declarar `@moura-solar/database` como dependência workspace de ambos, o grafo
passou a exigir `database#build` antes de `api#build` e `worker#build`, e o build
Docker sem cache passou. Não houve alteração de versões externas.

A primeira execução de `pnpm check` parou em dois testes DOCX porque o sandbox
bloqueou `spawnSync unzip` (`EPERM`). A repetição fora dessa restrição passou.
A varredura padrão do Prettier inclui as duas pastas não rastreadas preservadas;
elas foram excluídas apenas durante o check, e `.prettierignore` foi restaurado
byte a byte ao final. CI em um checkout limpo não contém essas pastas.
